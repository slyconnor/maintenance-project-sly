Maintenance Manager v5.7.0 — Setup checklist

WHAT IS NEW IN V5.7.0
- Admin Settings: email notification master switch.
- Select active engineers who receive NEW OPERATOR REQUEST emails.
- Optional extra recipient email addresses.
- Assigned engineer gets an email when a request is accepted/assigned.
- Optional low-stock email when a tracked part crosses from above minimum to at/below minimum.
- Admin "Send test email" button.
- Cloudflare send_email Worker binding named EMAIL.

A) ORIGINAL FILE / PHOTO STORAGE (R2)
1. Cloudflare Dashboard > R2 Object Storage.
2. Create a bucket named exactly: maintenance-attachments
3. Leave the bucket private. Do not add a public domain.
4. Deploy this project. wrangler.jsonc already contains the R2 binding:
   ATTACHMENTS -> maintenance-attachments
5. After deployment, open the maintenance Worker > Bindings and confirm an R2 binding named ATTACHMENTS exists.
6. Test by opening a job or machine and uploading a small photo/PDF.

B) PUBLIC OPERATOR QR REQUEST PAGE
1. Cloudflare Zero Trust > Access controls > Applications.
2. Create/open the self-hosted app named Maintenance Operator Request.
3. Destination:
   Subdomain: maintenance
   Domain: project-sly.uk
   Path: request
4. Policy: Bypass > Everyone.
5. Save the application.
6. Test /request from a private/incognito browser. It should NOT ask for a Cloudflare login.
7. The rest of maintenance.project-sly.uk must remain protected by the normal Maintenance Access application.

C) EMAIL NOTIFICATIONS
The Worker binding is already in wrangler.jsonc. Cloudflare Email Service still needs to be configured in your account.

Recommended if you have Workers Paid:
1. Cloudflare Dashboard > Compute > Email Service > Email Sending.
2. Onboard a sender domain/subdomain. A dedicated subdomain is safest if project-sly.uk already receives normal business email, for example notifications.project-sly.uk.
3. Let Cloudflare add/verify the required sending DNS records.
4. In Maintenance Admin > Settings, set From email to an address on that onboarded domain, for example maintenance@notifications.project-sly.uk.
5. Select the engineer recipients and/or add extra recipient addresses.
6. Press Send test email.
7. Once the test succeeds, enable maintenance email notifications and Save Settings.

Workers Free option:
- Cloudflare Email Sending to arbitrary recipients requires Workers Paid.
- On Free, Cloudflare can send to verified Destination Addresses.
- Go to Compute > Email Service > Email Routing > Destination Addresses and add each engineer/extra recipient that should receive notifications. Each person must click Cloudflare's verification email.
- Do not change existing company MX/SPF mail records blindly. If project-sly.uk already uses another email provider, review Cloudflare's Email Routing DNS changes first or use a dedicated subdomain where possible.
- Then use Admin > Send test email before enabling notifications.

NOTIFICATION BEHAVIOUR
- New QR request -> selected team recipients.
- Accepted/assigned request -> assigned engineer's profile email.
- Low stock -> selected team recipients, only when a tracked part crosses from above its minimum to at/below the minimum.
- Request/job saving never fails just because an email could not be delivered.
- Public request submissions have a per-machine rate limit to reduce notification spam/abuse.

No new D1 migration is required for v5.7.0. Notification settings are stored in the existing shared state.
